# 同步数据保护：第一阶段

本阶段保护账号级快照的未同步修改，解决刷新恢复、错误状态、并发覆盖和无界重试问题。尚未将全部模块迁移到按记录落库，也没有修改线上数据库函数。

## 行为

- 每个账号独立保存同步基线、最新待同步副本、发送中的副本和版本号。启动时先读取恢复记录；联网失败时保留本机缓存。
- 写入只有收到可校验的云端确认才标记成功。请求已提交但响应丢失时读取云端核对，不重复增加版本。
- 同一来源的标签页使用 Web Locks 串行发送；无 Web Locks 时仍在当前页面串行。多设备依赖云端版本校验保护。
- 并发修改基于共同版本比较；不同记录或字段合并。同字段、删除与修改、相同数字 ID 的新记录冲突不自动覆盖。
- 同标签页的陈旧内存写入前先与磁盘比较。无法合并的副本按账号和标签页持久保留。
- 繁忙和网络异常最多自动尝试 5 次，使用退避和随机抖动。联网、重新激活页面或手动重试可继续；无更改不写云端。
- 显示本机待同步、同步中、云端已保存、离线和冲突等状态。提供冲突选择和完整本机备份导出。
- 写入本机失败时明确提示可能尚未保存；导出包含内存副本。不得承诺存储空间不足时已持久保存。
- 账号切换后旧请求不能使用新账号凭据发送，也不能用旧响应更新新账号的同步记录。

## 升级和恢复

首次升级若发现本机和云端不同、又没有可靠的共同基线，保留本机副本并要求明确选择，不自动判定哪份更新。整份副本选择需要勾选确认，确认前保存两份恢复副本。

冲突窗口打开后会重新核对内容和云端版本。如果期间发生变化，要求重新核对，不复用过时选择。恢复记录损坏时停止同步，不清空数据。

## 验证

新增单元测试覆盖未发出请求前刷新、请求提交后撤回、断网刷新、响应丢失、繁忙重试上限、并发字段合并、同字段选择、旧缓存恢复、本机配额不足和账号切换。

桌面及手机浏览器使用隔离的模拟接口，验证真实 localStorage、Web Locks、刷新、冲突弹窗、备份下载和多标签页。既有课表、花名册、便签、学习、备课、出差等浏览器回归一并运行。不向生产接口写入测试数据。

## 分阶段发布与回滚

先发布测试环境验收，再决定线上发布。第二阶段再迁移分模块记录存储，保持每个模块一个数据源，并核对迁移前后的数量和内容。

旧客户端不认识新的待同步恢复记录。有待同步项的设备应先成功同步或导出备份，再回退版本；不可直接清空恢复记录或让旧客户端覆盖本机副本。
